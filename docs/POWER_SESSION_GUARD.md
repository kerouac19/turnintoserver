# PowerSessionGuard 实现设计

开发版通过 `SMAppService.agent` 注册包内 LaunchAgent。看护使用同一个签名可执行文件的 `--power-guard` 入口，在 GUI/AppState 初始化前分流。plist 位于 `Contents/Library/LaunchAgents`，`BundleProgram` 指向 `Contents/MacOS/turnintoserver`；仅在请求 Server Mode 时注册。

GUI 需要固定的 `pmset disablesleep 0/1` 授权，以及已获准且可访问的后台项。注册成功不等于就绪：准备租约前使用带版本的 ping，核对看护可执行文件、UID、进程启动标识和请求/响应 ID。

## 租约顺序

1. 持久记录原 `SleepDisabled` 值及绑定 GUI PID/启动标识的新租约；写入或同步失败时不激活。
2. 激活前再次检查原值，只有看护能执行固定电源操作，不接收任意命令或可执行文件路径。
3. 调暗前按 ColorSync 显示器 UUID 记录原亮度。看护再次读取实际合盖状态，迟到的 GUI 请求不能调暗已经打开的内建屏。
4. 释放、看护重启或 GUI 退出时恢复本实例持有的修改并读回验证。不会清除事先已存在的禁用睡眠状态；外部修改过的亮度保留，并记录待恢复错误。
5. 清除租约前先持久记录恢复进度。删除或响应失败可重试，不重复改写已释放的电源项；GUI 收到恢复确认后才注销后台项。

看护监测进程退出并检查启动标识，避免 PID 复用；GUI 每 5 秒续租，30 秒失联进入恢复。首次心跳失败即停止续租，不用后续心跳永久延长已经失败的会话。持有租约时使用允许系统空闲睡眠的活动标记避免 App Nap 干扰存活判断。睡眠通知暂停超时、尝试恢复并拒绝新激活，唤醒时重置联系窗口。

失败恢复保留记录并重试。后台项停用、注销、sudo 授权缺失、内建屏离线均有失败路径；用户级看护不能承诺在登录会话或后台运行许可已经消失后仍然即时恢复。

## 传输与适用范围

请求与响应是在当前身份专属 `Application Support/.../PowerGuard` 目录发布的有限大小 JSON；目录权限 0700，记录 0600。通过目录 dispatch source 处理请求，不常驻轮询邮箱。租约写入在确认前同步，进程锁排除第二个看护；协议版本、Bundle ID、UID、可执行路径、启动标识、随机请求 ID 和租约 token 用于拒绝过期或无关事务。

这是一条同用户邮箱通道，不构成对同一用户下任意恶意代码的认证隔离。现有 sudoers 已允许该用户调用两条固定命令。原版和开发版不能同时管理系统电源；其他工具也可以修改全局状态，因此此设计不是跨应用的通用电源设置仲裁器。

自动化使用内存系统适配验证 `PowerLeaseEngine`，不注册后台项、不执行 `pmset`。真实的 SMAppService 注册、睡眠唤醒和崩溃恢复，需要固定签名产物及真机验证后才能通过发行验收。
